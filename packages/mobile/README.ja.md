# kikori-mobile

Android のアプリの画面を、WCAG に照らして検査する、試験的な MCP サーバーです。ウェブページを監査する [kikori](https://github.com/vivil/kikori/blob/main/README.ja.md) のモバイル版にあたります。達成基準の番号、状態、判断の流れは、kikori と共通です。

kikori-mobile は、Deque Systems、axe-core、Google とは関係がありません。

> **試験的な機能です。** 検査は、保存しておいた画面の階層を使ってテストしています。幅広い実際のアプリでは、まだ試していません。出力は今後変わることがあります。

## 検査できること

| ツール | 達成基準 | 内容 |
|---|---|---|
| `check_android_screen` | 1.1.1 / 1.3.2 / 2.5.5 / 2.5.8 / 4.1.2 | Android のエミュレーターか実機に表示されている画面を読み取り、名前のない操作部品、小さいタッチターゲット、読み上げ順の食い違いを検出します |

UI Automator を通してアクセシビリティの階層を読み取り、次のものを報告します。

- スクリーンリーダーが読む名前のない操作部品 (画像は 1.1.1、それ以外は 4.1.2)
- 24dp に届かず、隣との間隔も足りないタッチターゲット (2.5.8) と、44dp に届かないタッチターゲット (2.5.5、レベル AAA)。文の中に置かれた小さいターゲットは、例外にあたることがあるので、要確認として報告します
- 階層の中での順序と、画面上の位置が食い違う要素 (1.3.2、要確認)

あわせて、読み上げの順序と、名前のない画像の一覧を返します。呼び出し側のモデルは、これを見て判断できます。Android の指針が勧める 48dp に届かないターゲットは、WCAG の不適合ではありません。プラットフォームと指針の出典を添えて、`data.platformGuidelines` に分けて返します。達成基準の番号、状態、`judgments` の扱いは、ウェブページの検査と同じです。

## 使い方

次のものが必要です。

- Node.js 22 以降
- Android SDK の Platform-Tools に含まれる `adb` (`PATH` を通しておきます)
- エミュレーター 1 台、または USB デバッグを許可した実機 1 台

```sh
claude mcp add kikori-mobile -- npx -y kikori-mobile
```

調べたい画面を端末で開いてから、エージェントに `check_android_screen` の実行を頼みます。

## 起動時のオプション

| オプション | 環境変数 | 意味 |
|---|---|---|
| `--lang <ja\|en>` | `KIKORI_LANG` | 検査結果やエラーの文面に使う言語。既定では、環境の言語設定に合わせます |
| `--serial <番号>` | `KIKORI_ANDROID_SERIAL` | 検査する端末のシリアル番号。`adb devices` で確認できます。指定しないときは、つながっている唯一の端末を使います |

検査する端末は、サーバーの起動時に決まります。ツールの引数からは変えられません。

## 入力

| 引数 | 意味 |
|---|---|
| `level` | 目標とする適合レベル。`A`、`AA` (既定値)、`AAA` のいずれか |
| `judgments` | モデルや人が下した判断の一覧。それぞれ `{ id, verdict, reason, evidence }` の形で渡します。扱いは kikori と同じです |
| `screenshot` | 端末のスクリーンショットを付けるかどうか。既定値は `false` |

## 出力

結果の形は、kikori の検査結果と同じです。`findings` に、達成基準、重み (`fail` か `review`)、説明が入ります。`checked` は調べた達成基準、`needsJudgment` は判断が要る達成基準です。これに、次のものが加わります。

- `criteria`: この検査が扱う達成基準ごとの状態
- `coreVersion`: 達成基準と状態を定めている、共通の核のバージョン
- `data.readingOrder`: スクリーンリーダーが読むと見積もった順に並べた要素
- `data.unnamedImages`: 名前がなく、操作もできない画像。装飾の可能性があります
- `data.platformGuidelines`: プラットフォームの指針に届かないターゲット。プラットフォームと出典が付きます
- `data.framework`: 画面を作っていると推定したフレームワークと、`readingOrderConfidence`
- `notes`: 検査していない範囲

指摘が 1 件もない結果は、適合の証明ではありません。適合を表明する前に、TalkBack を使った人による確認を行ってください。

## 限界

- kikori は、端末から読み取るだけです。読み取るのは、階層、画面の密度、求められたときのスクリーンショットです。タップ、入力、設定の変更は行いません。
- 検査するのは、表示中の画面だけです。スクロールできる領域のうち、画面の外にある項目は階層に現れません。そうした領域がある画面では、結果の `notes` でその旨を知らせます。WebView の中身は含まれないことがあります。
- 読み上げの順序は、階層の順序からの見積もりです。TalkBack は、画面上の位置や、アプリが指定した順序も考慮します。そのため、実際に読み上げられる順序とは違うことがあります。
- Jetpack Compose、Flutter、React Native、WebView で作られた画面では、読み上げの順序をフレームワークが独自に決めるので、見積もりは外れやすくなります。kikori は階層からフレームワークを推定し、`data.framework` に `readingOrderConfidence` とあわせて返します。
- 検査は、保存しておいた階層を使ってテストしています。幅広い実際のアプリでは、まだ試していません。
- iOS には、まだ対応していません。

## 開発

このパッケージは kikori のリポジトリの中にあり、`packages/core` の共通の核を、自分の成果物に含めてビルドします。

```sh
npm ci                                   # リポジトリの直下で実行します
npm test --workspace kikori-mobile
```

テストは、保存しておいた階層と `adb` の代役を使います。端末も Android SDK も要りません。
